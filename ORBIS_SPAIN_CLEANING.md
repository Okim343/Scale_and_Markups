# Orbis Spain cleaning: decisions and results

Companion to `ORBIS_SPAIN_EXTRACTION.md`. This stage turns the raw WRDS extracts into a GNR-ready
firm-year panel. GNR has **not** been run. The full numbers are in
`03_Empirical/02_orbis_spain/01_intermediary/cleaning_report.md` (gitignored, regenerated by the script).

## Run

```bash
python 03_Empirical/02_orbis_spain/01_code/01b_fetch_deflators_es.py     # Eurostat, public API
python 03_Empirical/02_orbis_spain/01_code/02_clean_orbis_es.py          # about 90 s
```

Both are restartable: the fetch script reuses saved downloads unless `--refresh` is passed, and the
cleaning script rebuilds every output from the raw extracts. `--include-2024` also writes
`gnr_ready_tfas_with2024.{parquet,dta}` for the robustness year.

### Feeding the existing GNR pipeline

`00_Hubmer_RTS/01_code/01_build_gnr_panel.py` reads Stata (`pd.read_stata`), so each GNR file is also
written as `.dta`. `03_Empirical/02_orbis_spain/01_code/config_gnr_orbis_es.yaml` is a copy of the
Compustat config with only these changes: input, variable mapping (`bvdid`, `rev_D`, `cap_D`, `mate_D`,
labor = `staf_D`), `start_year: 2014`, `build_materials_alt1: false`, larger row guardrails, export window
2015-2023, outputs under `01_intermediary/gnr*`, and **`publish_firm_year_to_alpha_pipeline: false`**.
The stage scripts are unchanged:

```bash
(cd 03_Empirical/00_Hubmer_RTS/01_code && \
  python 01_build_gnr_panel.py --config ../../02_orbis_spain/01_code/config_gnr_orbis_es.yaml)
```

An in-memory dry run of R1's `build_panel` + `trim_panel` (nothing written, no estimation) works on
`gnr_ready_tfas.dta`. It gives 3.12M rows with a consecutive lag, then 2.79M after the
`mate/rev in [0.05, 0.95]` band, then **2.68M rows and 553k firms** after the 1% trim, in 14 cells and 2015-2023.

## Decisions

1. **Country.** Drop `bvdid` not starting with `ES` (2,382 rows).
2. **12-month accounts.** Keep `nr_months == "12"` (text). Drops 224,613 rows.
3. **One account per firm-year.** Year = `closdate_year` (Orbis' own year; 98.8% of accounts close in
   December, so the Kalemli-Özcan et al. June rule would move about 0.3% of rows and is not applied). Among
   12-month accounts of a `(bvdid, year)`: U1 before U2, then the latest `closdate`, then a local-registry
   filing before an annual report. The raw keys are unique, so the rule is deterministic. Only 349
   firm-years were affected (698 rows): most of the 2,464 multi-account firm-years in the raw file were
   non-12-month accounts and were already dropped in step 2.
4. **Revenue** = `turn`, else `opre` when `turn` is missing. The fallback is used for about 0.9% of
   2015-2023 firm-years in the clean panel.
5. **Positivity.** Drop revenue, `mate` or `staf` ≤ 0 or missing. Capital is a flag, not a drop, in the
   clean panel: `pos_tfas` (baseline), `pos_fias` (robustness).
6. **Industry.** Core codes only. `naicsccod2017` is a 4-digit NAICS group; `naics2_raw` is its first two
   digits. GNR cells follow the existing pipeline's grouping (31-33, 44-45, 48-49), coded in the integer
   `ind2d` as 31 / 44 / 48 with the label in `sector_id`. Drop firms with a missing core NACE or NAICS code
   (31 rows).
7. **Deflation (baseline: HICP).** Every money variable is divided by Spanish HICP (`prc_hicp_aind`,
   CP00, annual average), 2019 = 1, exactly as Hubmer et al. App. C.3. Why not sector deflators:
   - Eurostat has **no Spanish output (P1) or intermediate-consumption (P2) deflator at A64**. Spain
     transmits P1/P2 in `nama_10_a64` only at current prices and publishes no supply-use tables at
     previous-year prices. The only A64 price index is the value-added deflator, a poor output-price proxy
     that swings wildly in 2021-22 (C19 refining 26 to 60, D35 electricity 93 to 336, 2019 = 100).
   - R1 computes the materials share as `s = m - r` from the deflated levels. Different deflators for
     revenue and `mate` would make `s` stop being the nominal share GNR's first stage needs, and R1 has no
     year dummies to absorb the gap. The Compustat input avoids this by using one GDP deflator for
     everything; HICP does the same here.
   - The downstream objects are nominal ratios anyway (μ = ε^m · rev / mate; within-year sales shares).

   **Robustness (`_Ds`)**: revenue *and* `mate` by the firm's A64 VA deflator (same index for both, so `s`
   stays nominal; A64 → section → TOTAL fallback when a cell is missing), capital by the section GFCF
   deflator (`nama_10_a64_p5`, P51G, N11G; Spain only reports it by section), `staf` by the GDP deflator.
   Firms are mapped to A64 by their **own core NACE division**, not through NAICS. The NAICS2 → NACE
   section crosswalk (`NAICS2_TO_NACE_SECTION` in the script) is a fallback only. The report checks it
   against firms' own codes: one-to-one for most cells, with 22 split D 71% / E 29%, 54 split M 82% / J 18%,
   and 23 split F 91% / L 9%. Book-value capital is at historical cost, so neither deflator makes it a
   true real stock.
8. **Panel.** One row per `(bvdid, year)`. Flags are computed within each GNR file, because the tfas and
   fias samples differ. R1 rebuilds the lags itself (consecutive years only). 2014 is a lag-only year: it
   has no 2013 lag, so R1 never uses a 2014 row as an observation. 2024 is in the clean panel but not in
   the GNR files.
9. **Sector exclusions** (NAICS2, dropped from GNR files, kept and flagged in the clean panel): 52, 53, 62,
   81 (Hubmer et al. / `main.typ`), 92, 99 (out of scope; no 99 in Orbis), and **55** (holding
   companies and head offices, whose revenue is largely intra-group; not in the paper's 14-cell set).
   **49 is kept**: the Compustat reason for dropping it (8-11 public firms, μ_cw < 1) does not apply, and
   Orbis has 12k window firm-years in 49. Exclusions remove 651k firm-years (all years); the largest are 81
   (216k in the window) and 53 (180k).

## Results

- Baseline GNR input: **3.80M firm-years in 2015-2023 (704k firms)**, plus 177k lag-only 2014 rows, so
  about 420-437k a year from 2016 on. That is in line with Hubmer et al.'s 3.8M over a much longer window.
- Log means and medians match Table A.4 (Spain): revenue mean 13.05 vs 13.08 and P50 12.93 vs 12.92; wage
  bill 11.64 vs 11.64. Intermediates have a fatter left tail (SD 2.33 vs 1.84; P10 8.95 vs 9.92), which
  R1's share band removes. With fias capital: mean 11.33 vs 11.07.
- Smallest cells (window): 21 mining 10.6k firm-years (1,661 firms); 22 utilities 20.1k (4,070 firms).
  After R1 trims: 7.5k and 10.5k rows. All cells are far above R1's 500-row minimum.

## Things to decide before GNR

- **Pooled vs within-cell.** The existing GNR pools all industries in one production function (industry
  dummies only in the step-2 Markov process). Hubmer et al. estimate **within** country × NAICS2. R1/R2
  have no cell filter, so within-cell estimation needs either per-cell input files or an Orbis-side
  wrapper. The Compustat GNR also used raw NAICS2 (31/32/33 and 44/45 separate); the Orbis file groups
  them as asked.
- **Runtime.** The R1 estimation sample is 2.68M rows, about 21× Compustat's 128k. Expect the multistart
  steps 1 and 2 to take tens of hours locally; Marvin2, fewer starts, or per-cell runs would help.
- **Services lose many firms to the share band.** `mate > 0` is the binding positivity filter (1.72M rows),
  and among survivors 11.9% have `mate/rev` outside [0.05, 0.95]. Medians are 0.09 in 61, 0.16-0.18 in
  54/56/71, so R1 drops about half of 54 (387k → 195k) and 61 (69k → 32k). The materials-based markup
  is therefore estimated on the goods-intensive part of services.
- **Implausible input shares.** `(mate + staf) / rev > 1` for 9.3% of window firm-years (18% in 11, 14% in
  61, 13% in 23); `staf / rev` P99 = 2.0. These are mostly small loss-making firms. R1 does not trim on
  `staf` shares, so consider a `(mate + staf) / rev` cap before the markup stage.
- **2015 lag coverage.** 2014 is a surviving subset of the rolling window, so only 35% of 2015 firm-years
  have a lag (vs about 85-89% from 2016). The step-2 sample is thin in 2015 (114k vs about 300k+ a year).
- **No 4-digit core NACE.** `naceccod2` is a 3-digit NACE group (`20.1`) for every firm. The only 4-digit
  code is `cnae2009_pcod` (national CNAE 2009 primary = NACE Rev.2 class), which is a *primary* code. The
  concentration stage must choose between NACE 3-digit core and CNAE 4-digit primary.
